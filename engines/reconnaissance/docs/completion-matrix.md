## Tools and test boundaries

Successfully exercised: HTTPX against real local HTTP fixtures, PyYAML/JSON
operation parsing, SQLite migrations/persistence, cryptographic signing,
documented/reference recursion, BloodHound export parsing, SBOM package parsing,
scope refusal and scanner-failure isolation. These are measured component tests,
not claims of live AD/cloud/Kubernetes security coverage.

Native Nmap, Masscan, RustScan, NetExec, Certipy, Docker, TShark and Trivy were
unavailable. `ldapsearch`, Git and Nuclei were detected; the new engine does not
claim them integrated. Nuclei has a separately exercised curated adapter only
in the legacy red-team application.

No Windows domain controller/AD CS, customer cloud credentials, Kubernetes
cluster, or production AI stack was supplied. Those dependencies prevent live
validation, and the corresponding live adapters still require implementation.
Skipped native tests are not passing tests. Fixture-only paths are explicitly
identified; no hardcoded network result is used in the runtime.

## Verified results

- Workspace regression suite: **118 passed, 2 skipped, 0 failed**.
- Fresh installed engine wheel, without the root red-team package:
  **60 passed, 2 skipped, 0 failed**. These repeat engine tests, not extra coverage.
- Dashboard JavaScript syntax and installer shell syntax passed.
- `examples/generated/sample-report.json`, `sample-report.html` and
  `lab-results.json` were generated by the installed engine against an actual
  ephemeral loopback HTTP fixture: 16 GET requests, two documented methods
  analysed, one approved GET observed, and no state-changing requests.
- Fixture operation precision/recall are measured against its configured two
  methods. This is not native port, AD, cloud, Kubernetes or AI-stack benchmarking.

Native full TCP/UDP certification and broad live integrations remain unfinished.
The two skipped tests require an installed Nmap and an authorized native lab.
